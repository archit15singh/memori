# Gate GitHub release announcements on successful registry jobs

When maintaining `.github/workflows/release.yml`, keep `github-release.needs` set to `[crates-io, pypi]` and its condition set to `startsWith(github.ref, 'refs/tags/')`. An `always()` status override allowed the announcement job to run after registry failures; removing it restores the default success gate while retaining the tag-only policy. Name the publication step `Create release`.

Verification performed with `.venv/bin/python` and `yaml.load(..., Loader=yaml.BaseLoader)`: assertions passed for both required registry dependencies, the exact tag-only condition, absence of `always()`, and replacement of `Create release even if registry jobs had failures` with `Create release`. These were static workflow checks; no GitHub Actions execution or real registry upload was tested.

Source: `.github/workflows/release.yml` in the public Lorevell repository; the exact fix revision is not recorded in this note.
